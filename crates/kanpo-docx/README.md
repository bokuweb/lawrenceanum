# kanpo-docx

官報の PDF を DOCX（Word）にする。PDF の字はそのまま読み、ページの画像（スキャンした本文）は OCR（[ndlocr-lite-rs](https://github.com/bokuweb/ndlocr-lite-rs)）の結果から読む。ライブラリと CLI（`kanpo-docx`）として使え、I/O を持たないので WASM でも動く（[`kanpo-docx-wasm`](../kanpo-docx-wasm)、`/kanpo-docx` のページ）。

## 仕組み

1. `page_images(pdf)`: ページに置かれた画像を取り出し、8 bit グレースケールに復号する（FlateDecode の 8 bit・1 bit、CCITTFaxDecode G4、DCTDecode。原本 3000 冊分の画像の形式を調べた）。ページの表示の向き（`/Rotate`）に起こして、字が正立した画像にする。どのページにもある、ほぼ白い背景の画像（黒い画素が 0.05% 未満）は除く。
2. `ocr_images(pdf)` が認識対象の画像を返し、呼出元が OCR する（ndlocr-lite-rs。CLI はネイティブ、ブラウザは WASM）。原本の表のセルに一意に対応する図は認識対象から除き、元の画像を保つ。認識領域の枠は画像の画素。`ocr_page` が、表示したページ全体の画素の枠（`kanpo_parser::OcrPage`）に写す。
3. `convert(pdf, ocr)`: PDF の字と OCR の結果を合わせて解析し（`kanpo_parser::analyze_item_with_ocr`。ネイティブの字と重なる OCR 領域は除く）、記事ごとに段落・本文の中の表（結合セル付き）・新旧対照表（2 列の表）を DOCX に書く（[docx-rs](https://github.com/bokuweb/docx-rs)）。記事の最初の行は太字にする。

## ライブラリ

表の列グリッドと結合セルの幅をWordへ明示する。解析した元の表と各セルの文字・位置が対応する場合は、原本の列幅比率を親セルの内幅に縮尺して使う。対応が一意でない表でも、列数に合う均等なグリッドを宣言する。本文の主な用紙方向が横向きならDOCXも横向きにする。罫線で確認した複数段ヘッダーでは、横結合・縦結合と中央揃えを保ち、対照表の左右に対応する入れ子の表は前の本文と区切ってページ先頭から始める。原稿番号・法令名による分岐や、参照RTFからの補充は行わない。

発令見出しは原本の行境界で段落を分ける。段落先頭の条番号と本文の間は、原本の文字矩形で確認した空きだけを全角スペースに写す。本文中の条文参照には適用しない。続きページの表は、隣接ページ・同じ新旧区分・列の境界が対応する場合にだけ、ヘッダーと本文のグリッドを統合する。細かい比較表は原本の幅を収めるために横向きにする。

公布文の直後に、原本で独立した御名御璽・年月日・署名・法令番号が並ぶ場合は、それぞれを独立した段落に戻す。標題は制定文・公布文に同じ文字列が記録されている場合に独立させ、連名の署名も元の行ごとに分ける。日付・人名は固定せず、署名中の語の空きは原本の文字矩形から計測する。署名の読み順がずれた場合は、同じ原本ページの日付・署名・法令番号の完全な位置関係が一意に対応するときだけ修復する。

原本の字形とCFF矩形から認定できた一本線・二重線を、欄全体の文字列が同一の場合に転写する。二重線は元のスカラー位置で結び、Wordへ書いた全欄の文字列とも照合する。OCRで文字が増えた欄への転写は保留し、他の対応済みの欄を独立して処理する。

原本の小字と親文字が対応するルビ、前後の本文字形で確認できた上付き・下付き、CFFの中空の枠も、欄全体の文字列とスカラー位置が対応するときだけWordの書式にする。ルビは親文字のRunを保持した`w:ruby`、指数は`w:vertAlign`、囲みは`w:bdr`で表す。枠として認定された描画字形を本文の「□」として重複させない。本文や注記の文字列検索で同じ文字の別の出現箇所へ書式を移さない。

入れ子の表が次ページへ続き、空欄が多いため通常の格子検出では段落になる場合も、直前の開いた複合見出し表と原本の列境界が一致するときに限り、独立した描画インベントリの罫線からセルを復元する。部分的な横罫線、空欄、最終行の全列結合を保ち、元の文字ID・書字方向・ベースラインとセルの所属を照合する。閉じた罫線を越える文字や欠けた列境界を補完しない。ページ越しに同じセルを結合する場合も、欄内の元の文字順と書式の位置が保たれることを条件にする。保てないときは編集可能なページごとの表として残す。

原本の黒い不透明な破線と、既存セルの辺全体の位置が対応する場合は、Wordでもその辺を破線にする。クリップ・曲線・未知の線色など対応を認定できない描画から補わず、元にない辺も閉じない。新旧の欄と表全体の文字・結合が対応することを確認し、継続表では元の表全体が入る一意の行範囲だけを使う。同じ表に異なる線種の出所が重なる場合は推測しない。

OCRのON/OFFにかかわらず、元の画像を元の解像度でDOCXに埋め込む。ONでは認識した文字も加える。縮小時も縦横比を保つ。表の文字・座標・結合範囲が一意に対応する図は元のセルに置き、縦書きの画像付き表は物理的な行列配置に戻す。OCRによる文字の追加などで本文の位置に対応できない画像も、元ページを示す付録に掲載する。

```rust
// OCR の結果を渡す（OCR しないなら空のスライス）。
let docx: Vec<u8> = kanpo_docx::convert(&pdf, &ocr_pages)?;

// OCR の手段を渡して、画像の認識から通して行う。
struct MyOcr;
impl kanpo_docx::OcrEngine for MyOcr {
    fn recognize(&mut self, image: &kanpo_docx::PageImage) -> anyhow::Result<Vec<kanpo_docx::OcrRegion>> { /* … */ }
}
let docx = kanpo_docx::convert_with(&pdf, &mut MyOcr)?;
```

## CLI

```bash
cargo run --release -p kanpo-docx -- input.pdf -o output.docx \
  --ndlocr /path/to/ndlocr-lite-rs --models /path/to/ndlocr-lite-rs/models
```

- 既定で、画像を ndlocr-lite-rs（`--features onnx` でビルドしたもの）の `recognize-page --trace-json` で認識する（`--structure-rules false`。官報の census で使ったのと同じ設定）。`--ndlocr`・`--models` は環境変数 `NDLOCR_BIN`・`NDLOCR_MODELS` でも渡せる。
- `--no-ocr`: PDF の字と元の画像で書く。画像中の文字は認識しない。
- `--ocr-dir DIR`: 認識し直さずに trace JSON を読む（1 ページの PDF は `DIR/{PDF の名前}.json`、複数ページは `DIR/{PDF の名前}-{ページ}.json`）。
- `--dump-images DIR`: 取り出した画像を PNG で書き出す（確認用）。

本紙第1749号 13 ページ（破産の公告、`/Rotate 270` の画像だけのページ）は、ネイティブの ndlocr-lite-rs で約 6 秒。ページの柱の字（PDF の字）は画像に含まれないので、ページ全体を描いて認識した trace にあった柱の誤読（「彗星」）は出ない。

## WASM

`kanpo-docx-wasm` の `pageImages(pdf)` がページの画像（`{page, width, height, left, top, scale, pageWidth, pageHeight, pixels}`）を返し、`convert(pdf, tracesJson)` が同じ並びの trace（OCR しない画像は `null`）から DOCX を返す。`figma/scripts/build-kanpo-wasm.sh kanpo-docx-wasm kanpo-docx` で `figma/src/wasm/kanpo-docx/` に作り、`/kanpo-docx` のページが読み込む。OCR はブラウザで動く ndlocr-lite-rs の WASM 版（`figma/src/wasm/ndlocr/`）で、モデル（約 150MB）は `VITE_NDLOCR_MODEL_BASE`（既定は同 origin の `ndlocr-models/`）から読む。

### 原本の文字サイズ

PDFの文字変換行列とページ変換を含む有効なポイントサイズを保持する。生の語文字列と原本の枠が一意に一致するグリフだけを使い、完全な段落／改正後／改正前の文字列と出力位置が一致した場合にサイズを付ける。同一サイズの原本セル、及び検証済みの文字由来情報も使う。ルビは親字・読みのサイズと原本の基線間隔、画像を含む表は配置縮尺も反映する。OCR追加後は最終解析の位置に再対応した原本文字だけを保持し、OCR文字自体のサイズは推測しない。既定値は原本文字数で最多のサイズとし、原本サイズがないAPI入力は10.5ptを使う。

表の余白は原本の列とセル内容が対応し、元グリフの正の行頭余白を測れる場合に限り、同じ比率の左右余白をWordに設定する。句読点のぶら下がりにより行末の文字枠が罫線に触れることを、行頭余白ゼロの根拠にはしない。Wordのフォント・禁則・改ページにより、PDFと行折り／ページ数は一致しない。

### 表の先頭行の改ページ

新旧対照表の欄見出しと、複数行を持つ通常表の最初の行は、次の行から離れてページ末尾に残らないようにする。通常表では各セルの最後の直接の段落にだけ`keepNext`を付け、データ行を繰返し見出しに変更したり、長い行全体を分割禁止にしたりしない。元画像を物理配置する表にはこの追加指定を行わない。入れ子になった複数行ヘッダーは、対応する左右の表を一つの帯として維持するための改ページを保持する。

### 原本の書体とセル内の寄せ

サイズが同じでも、条番号だけゴシック体という原本を区別する。元グリフのフォント名に明示されたMincho/GothicをWordの明朝／ゴシックに対応させる。Bold及びRegular/Light/Mediumが明示される場合だけ太字／通常の指定を付け、Gothicという書体名や不明なW番号から太字を推測しない。行全体の書体が混在する場合は、原本の語と完全な文字列・位置が対応する範囲だけ分けて保持する。

寄せは、原本と全セルの文字列・結合範囲が一致する表の元グリフ枠で判定する。セル内の各行が同じ行頭／中央／行末に揃い、十分な余白がある場合だけ適用する。縦組みの行末（下）寄せは横組みのWordでは右寄せになる。枠いっぱいの本文、複数の揃え方が混在するセル、出典が矛盾するセルは判定しない。元画像を物理配置する表は変更しない。

OCRが記事を末尾へ追加する場合、元のページトレースはネイティブ文字のままである。最終モデル全体と最終文書が一致し、元のフィールド全文がその先頭に残ることを確認できた場合に限り、元のグリフに対応するサイズ・書体をその範囲で保持する。途中の一致文字列を探したり、追加OCR記事の同じ綴りへ書体をコピーしたりしない。ルビ等の特殊装飾は従来どおり完全なフィールド一致の条件を使う。
