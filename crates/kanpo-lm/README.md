# kanpo-lm

[kanpo-parser](../kanpo-parser/) が組んだ官報の本文を、ModernBERT（穴埋めのモデル）で後から見直す後工程の crate。
パーサの中には組み込まず、パーサの出力（行のテキスト）だけを受け取る。

- `tagger::find_breaks`: fine-tune した切れ目の分類器で、各行の「本文の流れが途切れている所」を当てる（下の「切れ目の分類器」）
- `repair`: 分類器で見つけた怪しい行を切れ目で片に分け、片の並べ替え・単位の置き直しを候補にして、分類器から見て
  切れ目が無くなり、擬似対数尤度でも十分に自然になる候補だけを補正として返す（字を足したり消したりはしない）
- `scan` / `correct`: fine-tune していない ModernBERT の擬似対数尤度だけで同じことをする（分類器より弱い）

モデルは [sbintuitions/modernbert-ja-30m](https://huggingface.co/sbintuitions/modernbert-ja-30m)（約 155MB）。candle で CPU で
動かす（GPU も外部のライブラリも要らず、WASM にも載る）。各トークンを隠して前後の両側の文脈から当てる擬似対数尤度で
採点し、16 トークンおきの位置をまとめて隠す（`MlmScorer::stride`）。採点器は `Scorer` トレイトで差し替えられる。

## 言語モデルで分かること・分からないこと

| 使い方 | 結果 |
|---|---|
| 字を入れ替えた行と元の行を比べる（語の移動・他の行の断片の混入・行の前後の入れ替え、計 599 組） | 崩した方を低く見るのが 99.0%・98.0%・94.5%（1 つずつ隠す採点とほぼ同じ） |
| 1 行だけを単独で見て崩れかを決める | AUC 0.75〜0.82（表・一覧・列の途中で切れた縦書きの行も読みにくく見える） |

比べるのは得意で、単独で決めるのは苦手なので、`scan` の結果は人が見る順番を決めるため、`correct` は書き直しの
候補どうしの比較だけに使う。前後両側を見るので、近くの行に同じ文があると崩れた行もそこから当てられて読みやすく
見える。表の行の片を並べ替える候補は、同じ字の並びが隣り合う方を好んで誤る（「資産合計　13,295,943　負債・純資産合計
　13,295,943」の金額を後ろにまとめる方が 38.8 nat 勝つ）ので、既定では試さない（`Options::segments`）。

試作では Gemma 4 E2B（llama.cpp、4.97GB）とも比べた。候補どうしの比較の精度は同じくらいで、怪しい所の洗い出しは
Gemma の方が少し強かったが、モデルの大きさと動かす手間に見合わないので使っていない。

## 切れ目の分類器（fine-tune）

ModernBERT-Ja-30m を、トークンごとに「直前から本文の流れが途切れているか」を当てる分類器に fine-tune した（`train/`）。
正しい本文（e-Gov の法令 204 件の本文を縦書きの列の幅で折り返した行と、蓄積した官報の今の本文の行）に、パーサの失敗に
似た崩し（縦組みの列の逆順の連結・列の入れ替え・断片の混入・語の移動・行の前後の入れ替え・縦中横の単位のずれ・上付きの
字の分離）を入れ、各字の元の位置から切れ目のラベルを付ける。学習は 75,755 例を 2 周（Apple M 系の GPU で 70 分）。

| 評価 | 分類器 | fine-tune 無し（擬似対数尤度） |
|---|---|---|
| 人工の崩し（法令・ページ単位で学習と分けた 2,551 例）: 例に崩れがあるか | AUC 0.991（切れ目のトークンの適合率 0.87・再現率 0.90） | — |
| 本物の崩れ: 横組みのページの中の縦組みの公告が逆順につながった行（#163 で直す前の 100 ページの 281 行）と直した後の行 | AUC 1.000。確率 0.9 以上で崩れた行を全部拾い、直した後の行は 0.1% | AUC 0.727 |
| 本物の崩れ: 縦中横の単位がずれた行（8 行） | 7 行が 0.97 以上、1 行が 0.59。単位を含む正しい行は最高 0.20 | — |
| 今の出力の 40 ページ | 確率 0.5 以上は 2,125 行のうち 20 行。半分ほどは本物の不具合（ToUnicode の無い外字が落ちた行「国土交通大臣は、の取組状況等がの判断」、決算公告の見出しの崩れ、表の欄のつながり）、残りは表の欄の断片 | — |

`repair`（分類器で選んだ行の補正）の確かめ（`train/make_repair_eval.py` で、学習に使っていない法令などのまとまりの 1 行だけを崩した
120 ページと、崩さない 80 ページ）:

- 行の前後の入れ替え 54 行のうち 43 行、語の移動 66 行のうち 36 行を元の行に戻した（擬似対数尤度の改善の下限 15 nat）。
  誤った書き直しは 4 行（括弧閉じが残るなど、元の行に近づいたが戻り切らないもの）、崩した行とは別の行の書き直しは 1 行
- 崩していない 80 ページと、今の出力の 40 ページの書き直しは 0 行
- 縦中横の単位がずれたページ（パーサを直す前の 4 ページ）は 6 行を補正した
- 縦組みの列が逆順につながった行は、切れ目は当てるが直せない（片を逆に並べても、間の横組みの見出しなどで元に戻らない）。
  この崩れはパーサで直してある（#163）

分類器の重み（約 147MB）はリポジトリに入れていない。`train/README.md` の手順で作る。

## 補正の確かめ方と結果（fine-tune 無し）

`check` を、パーサを直す前（縦中横の単位の位置が崩れていた版）の 4 ページと、今の出力から無作為に選んだ 40 ページに
掛けた（既定の設定: 見直す行は文脈付きで 1 字 0.5 nat 以上、書き直しを採るのは 25 nat 以上の改善）。

- 直す前のページ: 7 行を補正し、5 行は正しい行に戻った（「四三三・六七　を超え四三四・一七MHz　以下…MHz」→
  「四三三・六七MHzを超え四三四・一七MHz以下…」など。改善は 33〜64 nat）。残る 2 行も単位は数の直後に入ったが、空白や
  語の中に入り込んだ単位（「を超GHzえ」）が残った。上付きの字が別の行になった行（「10　＋15）Hz」）は字が足りないので
  直せない
- 今の出力の 40 ページ: 補正は 0 行（単位の候補が勝ったのは 1 行で 0.2 nat）

## 使い方

```bash
mkdir -p ~/.cache/kanpo-lm/modernbert-ja-30m && cd ~/.cache/kanpo-lm/modernbert-ja-30m
for f in config.json tokenizer.json model.safetensors; do
  curl -LO https://huggingface.co/sbintuitions/modernbert-ja-30m/resolve/main/$f
done
cd -

# パーサの出力を書き出して（kanpo-parser の README の textdump）、補正の TSV を出す
cargo run --release -p kanpo-parser --example textdump -- .cache/kanpo-archive /tmp/after
cargo run --release -p kanpo-lm --example check -- ~/.cache/kanpo-lm/modernbert-ja-30m /tmp/after
# 怪しい行を上から 100 行
cargo run --release -p kanpo-lm --example check -- --scan 100 ~/.cache/kanpo-lm/modernbert-ja-30m /tmp/after

# 切れ目の分類器（train/ で作ったもの）: 切れ目の確率の高い行から 100 行（切れ目の前に「|」）
cargo run --release -p kanpo-lm --example breaks -- --top 100 ~/.cache/kanpo-lm/breaks-30m /tmp/after
# 分類器で怪しい行を見つけて直す
cargo run --release -p kanpo-lm --example check -- --tagger ~/.cache/kanpo-lm/breaks-30m ~/.cache/kanpo-lm/modernbert-ja-30m /tmp/after
```

パーサを直したときの前後の比較（変わった行だけを採点して、どちらが自然か）にも使える。
