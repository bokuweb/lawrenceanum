# テーマ追跡の試用と課金検証

2026-10-24。基本の検索・Wikiを無料で育てながら、継続調査で短縮できる時間と支払う理由を検証する。
最初の対象は「生活保護・行政救済」。判例、当時の条文の版候補、改正履歴、関連Wiki、原文をたどる既存機能を利用する。

## 今回の試用版

- `#/watch` でテーマに一致する収録資料と一致した語を表示する。
- 追跡設定・既読・自分の調査メモをブラウザの localStorage に保存する。追跡中はダッシュボードに未読件数を出す。端末間の同期はない。
- 「現在の一覧を次回の比較基準に保存」で、絞り込み前の一覧をブラウザに記録する。次回は収録候補の追加と、同じ種別・日付・URLのタイトル・判示事項などの表示情報の変更を区別し、「追加・変更のみ」で絞れる。追跡中のテーマはダッシュボードにも追加・変更件数を表示する。変更前の表示情報も開いて確認でき、Markdown出力には基準日時・変更区分・変更前の表示情報を含める。既読や調査案件とは独立する。
- 基準は明示的な操作で更新する。公表日以降の新着や本文・Wiki・条文の改変を検出する機能ではない。古い裁判日の追加も候補に含め、一覧から外れた資料は削除と判定しない。取得失敗時や基準より古い配信は差分を判定せず基準の更新を停止する。保存データが不正な場合は比較基準だけを無視する。比較基準は最大1,000件・表示情報のJSON計100万文字まで。
- `feeds/topics/administrative-welfare.xml` をRSSリーダーで購読できる。メール・プッシュ配信は未実装。
- 表示中の資料をMarkdownに出力する。確認先URL、判例の裁判所出典、判示事項、一致した語、収録範囲、自分のメモを含む。
- 判例のページから既存のLLM要約・解説、関連Wiki、条文の版候補へ進める。LLM生成であることと出典確認の案内は維持する。今回の調査メモ出力ではLLM生成を行わない。
- テーマ一覧の判例を2件まで選び、公式の判示事項・裁判要旨・結果・参照法条を並べて比較する。条文への言及から既存のサイト内の版候補へ進める。公開済みWikiがあればLLM生成と明記した概要を表示し、引用根拠付きの解説をその場で開ける。
- 判例詳細・公開済みの判例Wikiから1件、関連判例欄から表示中の判例との2件を比較候補として持ち込める。テーマ一覧の収録範囲外も対象にできる。`#/watch?case=97208&case=97210` は候補の提示だけを行い、保存先・事件名・裁判所公表の判示事項・現在と変更後の比較対象を確認してから保存する。上の案件欄で保存先を切り替えられる。
- 既存対象と合わせて2件以内なら追加し、上限を超える場合は持ち込んだ1〜2件への入れ替えを明示する。候補を閉じるだけでは比較を変更しない。外した判例のメモや別案件は保持する。候補のID不正・取得失敗・別事件の応答・保存データの読み込み失敗では追加を停止し、書き込み失敗では成功と案内せず再試行できる。関連条文の一致を法的な先例関係と扱わない。
- 比較対象と判例ごとのメモも同じブラウザに保存する。各メモは2,000文字、最大100件。比較対象は未読の絞り込みやフィードの更新で一覧から外れても残る。比較メモのMarkdown出力には公式データ、原文・条文候補・公開済みWikiへのリンク、自分のメモを含める。AIの解説本文は出力に含めない。
- 比較する判例は利用者が選ぶ。事案の同一性・法的評価・判例変更を自動判定する機能ではない。公式データの未収録、取得失敗、AI解説の未収録を区別する。判例IDが一致しない応答は表示・出力せず再試行を案内する。
- 2判例の抽出条文を法令ID・条番号で照合し、共通と片方のみを一覧にする。各判例の項への言及、現在の原文データと一致する抽出箇所、版選定の根拠、判例ごとの条文候補、公開済み法令Wikiをたどれる。未抽出を言及なし・適用なしと扱わず、項・適用版・争点・先例関係の一致も判定しない。取得失敗・別事件の応答・確認中は分類を保留する。比較メモ出力にも抽出結果・確認先・未確認状態を含める。
- 名前を付けた調査案件を最大10件保存できる。案件ごとに比較対象2件と判例のメモを分け、「調査する問い」「確認した出典・箇所」「未確認の点・次に調べること」を記録する。現在の比較をコピーして案件を作成し、切り替え・再訪後に再開できる。案件を選ばずに行った比較も別に保持する。
- 案件の変更は同じブラウザに自動保存する。「案件の記録を出力」は判例0〜1件や取得失敗時にも利用でき、調査記録・確認先リンク・比較対象から外した判例のメモも出力する。「比較メモを出力」は2件の読み込み後に公式要旨も含める。出典の確認記録は利用者の記入であり、システムによる検証結果ではない。資料は再開時に読み直すため、保存時の資料を固定する機能ではない。

ルールは `config/watch-topics.json` でRust生成処理と画面が共有する。タイトル・説明（判例では裁判所公表の判示事項）・対象法令名への文字列一致であり、本文全体の検索や法的な関連性の判定ではない。
テーマ抽出は全体フィードの件数制限より前に行う。各種別最新50件まで。法令更新は直近14更新日分、官報は直近30日分の収録ファイルが対象。ほかの資料も収録済みインデックスの範囲に限る。
判例は裁判日順で、公表・取得順ではない。古い裁判日の資料が後から収録されても件数上限により表示されないことがある。未読は収録中の資料の確認状態であり、前回訪問以後の新着件数ではない。
欠落・取得失敗を「更新なし」と扱わない。条文候補は適用法条の確定ではなく、原文・経過措置の確認が必要。

## 次に人に確認すること

まず生活保護・行政救済を継続して調べる弁護士、支援実務者、企業法務等の5〜10人に試してもらう。募集・連絡・個人情報の収集・課金は今回実施していない。
以下を2〜4週間、本人の同意を得て聞き取る。閲覧数を支払意思の代用にしない。

1. 普段の調査テーマ、頻度、確認する出典、更新を見逃した際の具体的な困りごとを聞く。
2. 同程度の調査課題で、普段の方法と試用版それぞれの「必要な出典確認まで」の時間、漏れ・誤検出、迷った箇所を記録する。要約だけ読む時間で比較しない。
   同じテーマの2判例について、事案・結論・理由・適用時点の相違を原文で確認し、比較メモに出典と未確認の点を残す課題も試す。画面の往復と翌週の調査再開にかかる時間を確認する。
   同じ判例を使う別の案件も作成し、問い・メモを混同せず切り替えられるか、翌週に出典確認と未確認事項の続きから再開できるかを確かめる。
   判例・Wikiの関連候補から新着一覧にない判例を比較へ持ち込み、保存先の案件や入れ替える対象を迷わず確認できるかも試す。
   共通条文でも項や適用版が異なり得る2判例を使い、条文比較から各事件の言及箇所・版の根拠へ進む時間、片方の未抽出を「言及なし」と誤認しないかも確認する。
3. 自発的に週何回戻ったか、RSSから確認した資料、調査メモの利用例を聞く。操作の自動追跡は現時点では行わない。
   前回の一覧を保存し、次週に追加・変更の候補から原文へ到達するまでの時間を確かめる。未読と追加・変更の違い、裁判日と公表日の違いを誤認しないかも確認する。
4. 「継続するなら何が必要か」「月5,000円なら継続するか」「予算の決裁者と条件」を具体的に確認する。口頭の好意と実際の購入意思は区別する。

## 価格と開発順の仮説

価格は検証用で、販売中のプランではない。

| 順番 | 機能 | 仮説 |
| --- | --- | --- |
| 1 | 一分野の新判例・法改正通知と解説 | 月3,000〜10,000円。まず月5,000円で継続したい理由を確認 |
| 2 | 案件ごとの保存・比較・出典付きレポート | 月5,000〜15,000円。具体的な調査案件での利用を確認 |
| 3 | 構造化した法情報のAPI・MCP | 開発企業との個別契約。再配信条件・運用要件も確認 |

試用の結果を踏まえて、必要な出典・過去版の収録、誤検出の削減、解説の根拠、日付・取得履歴を改善する。
月5,000円で継続したい利用者と具体的な条件が見つかったら、認証・同期、同意に基づく通知先登録・配信停止、配信履歴、決済へ進む。収集時刻に基づく新着通知もこの段階で検証する。
大規模な課金・権限基盤の構築は、その検証後に判断する。
