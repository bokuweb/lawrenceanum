# 今後取得する判例の LLM Wiki

## 仕様（2026-10-24 更新）

- 既存の 44,974 件を一括要約しない。初回の `wiki-plan` は有効な判例索引を基準として保存し、判例の詳細取得・LLM タスク生成は行わない。以降、その索引に初めて現れた ID を対象にする。裁判日や ID の大小では判定しない。
- 基準・新規 ID・初回検出日・未完了状態を wiki ブランチの `.lawpub/hanrei-intake.json` に永続化する。索引の欠落・取得失敗で基準を作らない。上限超過、本文なし、取得失敗、LLM 未完了は翌回以降に再試行する。日付窓で取りこぼさない。`--max-hanrei`（既定 3、0 はタスク無効）と候補取得上限で費用を制限する。
- 新規取得時のみ全文 PDF の抽出テキストを判例 JSON に追加保存する。既存キャッシュは取り直さない。PDF 不在・抽出失敗はメタデータを残し、Wiki では判示事項・裁判要旨だけを根拠にできる。根拠本文がなければ要約しない。
- `hanrei/{case_id}.md`（`type: hanrei`）に事件番号・裁判所・裁判日・結果・収録範囲・原文 URL と LLM 区間を作る。新形式（版3）では要約・事案・争点・結論・判断と理由・射程・留意点・法令との関係の7節を作り、説明した各節にその判例自体の引用を必須にする。結論では認めた内容・退けた内容・差戻し等の対象と範囲を、射程・留意点では裁判所が示した条件・例外・留保だけを原文の裏付けとともに説明する。結果欄から理由を補ったり、他事件への一般化や実務上の助言を創作したりしない。裏付けのない節は「確認できる資料がありません。」と明示する。冒頭の要約は必須。既存の4節・5節形式は再生成せず引き続き読み込める。新しい構成は今後の新規取り込み・未完了の再試行に適用し、過去分の一括要約や完了済みページの再要約は行わない。
- 裁判所の「判示事項」「裁判要旨」は AI が書き換えず、別の固定区間に原文・出典を掲載する。空欄は「取得した公開データには記載がありません。」と表示する。固定資料との照合でこの区間の書き換えも検出する。
- 判例詳細の解説と判例 Wiki では、本文の第2・第3レベルの見出しが2つ以上あれば目次を表示する。Markdown の構文木から作り、コード例・引用内の見出しや脚注番号は含めない。同名の見出しも個別に移動でき、移動先へキーボードのフォーカスを移す。サイト内ルート・脚注・LLM生成の注意書きを保ち、動きを抑える設定では即座に移動する。既存の解説を表示時に整理するため、再要約やデータ再生成は不要。
- 既存の法令参照抽出を再利用し、参照された法令・条番号から法令 Wiki へのリンクを作る。条文の引用は画面リンクと共通の選定処理で過去版候補を取得する。本文の出来事の日付・期間、法令名を伴う明示的な「改正法による改正前」の記載を手掛かりとし、不明なら裁判日を暫定参照する。適用条文の確定とは扱わず、経過措置・遡及適用は未確認と明記する。条文への言及だけで適用・判例変更・一般的な結論を推測しない。法令不明でも判例ページは作成できる。
- LLM に渡す資料（判例の原文・関連条文）は wiki 内に固定し、`hanrei:ID#資料ID` の引用を原文・URL と照合する。根拠とページの版を結び付ける。未完了の雛形を完了扱いにしない。
- 完了後、法令ページから関連判例へ戻れる一覧を再生成する。判例同士も、同じ法令・条番号への言及がある場合に共通条文を示して最大10件結ぶ。共通条文の数・ページパスの順で決定的に並べる。先例関係・争点や判断・適用版の一致は推定しない。相対リンクは既存の Wiki グラフにも反映する。既存の日次 `Update LLM wiki` の plan → LLM → finalize → check → export に組み込み、画面では「判例」種別として表示する。

## 判例詳細の解説表示

公開済みの判例 Wiki がある場合、判例詳細の本文の前にも AI の要約・解説を表示する。公式の判示事項・裁判要旨と区別し、引用脚注・関連法令リンク・入力範囲の注意を維持する。Wiki と判例本文は相互に移動できる。未公開の解説は取得せず、旧配信形式では Wiki へのリンクを表示する。読み込み失敗は本文の閲覧を妨げず、解説だけ再試行できる。

判例詳細・判例 Wiki の出典脚注では、その脚注のラベル・参照資料と保存済みの引用が対応する場合に「この脚注の引用を原文で確認」を表示する。同じ資料からの引用が複数あっても他の脚注の引用を混ぜず、完全一致した引用の前後各100文字を表示する。Wikiでは開いたときだけ原文を取得し、取得失敗はその場で再試行できる。一致しない場合は保存時の引用と不一致の注意を示す。脚注・戻るリンクはサイト内ルートを保ち、キーボードのフォーカスも移動する。比較画面内の解説から原文へ移動する場合は、判例詳細の該当区間を開く。一般の引用一覧と裁判所への出典リンクは引き続き使え、旧配信や対応を確認できないページに確認欄は追加しない。LLMの再実行・データの再生成は不要で、引用の一致は解説の意味的な正しさを保証しない。

export は完了状態に加えて固定資料・収録範囲・参照条文・入力範囲との対応も照合し、不一致の判例ページを索引・本文 JSON・グラフから除外する。判例詳細側も事件 ID と資料の fingerprint の対応を確認する。表示用の `hanrei_explanation` は既存の LLM 区間から抽出し、追加の LLM 呼び出しは行わない。これらの照合は、解説の意味的な正確性の検証ではない。

同じ法令・条番号に言及する公開済み判例を、詳細画面にも最大10件表示する。共通条文数の多い順に、裁判日・裁判所・AI による概要を添え、判例本文・Wiki・表示中の事件の条文版候補へ移動できる。新規作成ページは裁判所も構造化して保存し、固定資料との対応を照合する。裁判日は取り込み日とは区別し、旧ページの欠落情報は「未記録」とする。先例関係・同一争点や結論・適用版の一致は推定しない。

判例一覧・判例詳細・Wikiの概要と解説には、LLM（大規模言語モデル）が生成した文章であることを明記する。判例詳細とWikiの関連判例欄では、公開済みの関連候補内を法令ID・条番号の組合せで絞り込める。同じ条番号でも法令が違えば別の条件とし、件数は最大10件の候補内であることを示す。各候補の概要にもLLM生成と表示し、共通条文の版候補・判例本文・判例Wiki・公開済みの法令Wikiにリンクする。Wikiの関連欄はグラフの取得に依存せず、事件ID・資料のfingerprintが対応するときだけ表示する。

export のたびに公開対象だけで判例間の関連データと固定 Markdown 区間を再計算する。不一致で公開対象から外れた判例への古い関連リンクを残さず、グラフにも現在の関連を反映する。元の Wiki ファイルは export で書き換えない。画面側も公開索引に存在する関連先だけを表示する。

判例詳細では「引用箇所を原文で確認」を開くと、判例自身の引用と配信中の判示事項・裁判要旨・PDF抽出本文を完全一致で照合し、最初の一致箇所の前後100文字と原文区間への移動ボタンを表示する。export は脚注の引用文・資料種別・事件IDを構造化して渡し、別事件や法令の引用を混ぜない。不一致や本文未収録なら保存された引用と注意を表示し、対応箇所を推測しない。これは文字列の照合であり、解説の意味的な裏付けや資料全体の版一致を保証しない。旧配信形式で引用データがない場合は従来の脚注を使える。

## 解説用の入力範囲

引用を検証する正本は全文の固定資料。LLM には合計36,000文字までを渡す。判示事項4,000文字、裁判要旨6,000文字、PDF本文22,000文字、各関連条文4,000文字の順に、全体予算の範囲で選ぶ。長い資料は冒頭・中盤・末尾から別々の抜粋にし、末尾を多めに残す。原文内の文字位置を記録し、離れた抜粋を連結した原文として扱わない。識別情報側の本文・要旨の重複は入力から除く。

選択範囲と文字数は固定資料・frontmatter に保存し、画面に入力文字数と欠落の注意を表示する。文字数は関連条文も含む原資料全体の合計であり、意味的な網羅性は示さない。多数意見・反対意見・当事者の主張を混同しないよう生成指示を明示するが、引用一致や構造検証だけで解説の正しさは保証できない。

## 運用

新規取得に加えて、過去分の要約・リンク解析・Wiki化を少件数ずつ日次で進める。新規最大3件・過去最大20件/日で、公開反映まで進捗を確認する。設定・再試行・公開確認の詳細は [日次バックフィル運用](hanrei-daily-backfill-plan.md) を参照。

過去分を指定して試験追加する場合は、`Update LLM wiki` の手動実行で `hanrei_case_ids` に公開済みの事件IDをカンマ区切りで最大10件指定し、`max_hanrei` で処理上限を指定する。CLIでは `lawpub wiki-queue-hanrei --wiki wiki --case-ids 97208,85148` で同じ待ち行列に投入する。完了済みページは再投入せず、新規取得の基準・既存の再試行回数も維持する。過去分の自動選択は別の `max_hanrei_backfill` 枠で行い、手動実行時は既定0件。生成後は通常と同じ引用検査・finalize・公開処理を通す。

CLI の `--max-hanrei` または環境変数 `WIKI_MAX_HANREI` で1回の上限を指定する。日次 workflow は既定3件を処理し、リポジトリ変数 `WIKI_MAX_HANREI` でも調整できる。初回は基準の記録だけであり、次回以降に配信索引へ追加された判例から要約する。これは裁判所の全掲載判例・全判決を網羅する約束ではない。引用の原文一致は意味的な正確性の保証ではなく、法令版は機械選定した候補であり、適用関係の確定は行わない。

## 判例画面の条文リンクと Wiki の共有データ

`link-laws-and-hanrei` は逆引きに加えて `links/hanrei-to-laws/{case_id}.json` を生成する。判示事項・裁判要旨・参照法条・PDF 抽出本文・既存の本文引用断片を同じ辞書で解決し、「生活保護法３条、８条２項」の省略された法令名・項番号にも対応する。表示のオフセットは UTF-16。画面では原文と抽出文字列が一致する箇所だけをリンクする。

候補には法令・条番号、根拠日付・抜粋、選定区分、版 ID・施行日・本文収録状態、判例／法令 Wiki パスを保存する。日付が複数・期間が複数版にまたがる場合は候補を併記する。法令履歴が対象時点まで遡れない場合は不足を表示し、本文未収録の版を別の版で代用しない。適用版候補が空の場合も、収録履歴の古い順に重複を除いて最大3件を `reference_versions` に保存し、サイト内で参考表示できる。適用版は未特定のままとし、対象期間後の版や改正の有無が未確認であることを明示する。旧配信で同フィールドがない場合は画面で履歴から補う。参考候補の本文は Wiki の固定資料・LLM 用引用には追加しない。改正前の指定があるのに改正法を対応付けられない場合も裁判日や現行版に置換しない。

自動処理は定型表現だけを対象とする。「同日」の照応、年だけの処分日、法令の経過措置、事件内で法令ごとに異なる適用時点などは確定しない。本文中の出来事は別法令・比較対象の事件の可能性もあるため、選定結果は常に候補として扱う。

判例→条文画面は選定版だけを取得し、条・項を表示する。裁判所の原文ページ・全文 PDF に直接リンクし、版候補の切り替えや Wiki の条文リンクもサイト内の同じ条文画面で扱う。本文未収録時も公式資料への導線は表示する。判例・法令 Wiki は公開索引に存在するものへリンクする。Wiki planner も同じ resolver で版を選び、版・根拠を `referenced_articles` と固定資料に保存して法令 Wiki と相互に紐付ける。既存の初回基準・新規判例だけの生成・件数予算は維持する。リンク生成そのものは LLM を呼ばない。

導入時は `link-laws-and-hanrei --public public` を再実行して新しいリンク JSON を配信する。日次の `update-law-data` は既存の実行箇所でこれを生成する。UI のみの再配信ではリンク JSON は増えないため、法令データに更新がなければデータ更新を force 実行する。
